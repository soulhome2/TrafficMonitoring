# Прототип: «Транспортные потоки» на математике RoadAR

Прототип веб-интерфейса вертикального решения для Интеллект X (ITV). Решение
считает, классифицирует и ищет транспортные средства на аналитике Traffic Analysis by
RoadAR. Демо-данные — пилот Hai Phong Port, 8 каналов. Два языка (RU / EN), две темы
(тёмная / светлая), дизайн-схема ONE PSIM.

- **Статус:** 🟡 черновик, на обсуждение с менеджером проекта
- **Обновлён:** 2026-10-14
- **Опорный документ:** [`Specifications/Traffic_Specification_RoadaR.MD`](../Specifications/Traffic_Specification_RoadaR.MD) v1.0.
  Он собран из `ТЗ_видеоаналитика_ТП_HaiPhong_RoadAR.docx`, красные пункты
  вынесены в раздел 13.

## Зачем он нужен

Прототип проверяет **сквозной сценарий пилота** (п. 9.2, раздел 11 спецификации).
Оператор видит ТС на видео, ищет все ТС этого класса, открывает проезд в архиве,
смотрит траекторию и строит отчёт по полосе. Канал, полоса, класс и период переходят
между шагами без повторного ввода. Текущий контекст всегда показан в шапке.

В интерфейсе есть только то, что может RoadAR. Стоп-линий, зон очередей, пешеходных
переходов, цвета ТС, СИМ, экстренных служб и других красных пунктов в нём нет.
Об их отсутствии честно сказано там, где оператор стал бы их искать: в настройке
сцены, в атрибутах ТС и в списке классов.

Прототип не заменяет спецификацию. Если поведение прототипа и текст документа
расходятся, прав документ, а расхождение записывается в `CHANGELOG.md`.

## Как открыть

Двойной щелчок по `index.html` в Chrome, Edge или Firefox. Сервер и сборка не нужны.

- Шрифт Inter встроен в `kit/kit.css` (base64), поэтому работает и под `file://`.
- Иконки Lucide загружаются с `cdn.jsdelivr.net`, для них при первом открытии нужен
  интернет. Без сети вместо иконок будут пустые места, логика от этого не меняется.
- Язык запоминается в `localStorage` (`traffic-lang`), тема — тоже (`kit-theme`).
  Демо-данные при каждом открытии генерируются заново, но всегда одинаково.
- Можно открыть сразу нужный экран через адрес: `index.html#report`, `#search`,
  `#video`, `#events`, `#scene`.

## Экраны и пункты спецификации

| Экран | Что показывает | Пункты |
|---|---|---|
| Обзор | ТС за сегодня, доля автопоездов, средняя скорость, каналы, открытые события; столбцы по классам за час и кольцо состава потока | 7.1, 3.1, 4.1 |
| Видео и траектории | Живое видео и архив по 8 каналам: рамки с классом и ID, пройденный путь (сплошной) и прогноз (пунктир), линии подсчёта и зоны. Клик по линии открывает мини-отчёт полосы. Справа лента пересечений линий | 2.2–2.6, 3.1, 1.2 |
| Карточка ТС | Траектория и стоп-кадр всего пути (пройдено — зелёный, впереди — синий), воспроизведение проезда через зону. Атрибуты: класс и подкласс RoadAR, прицеп, кузов, марка, скорость, уверенность. События с участием ТС | 2.4–2.6, 4.1, 4.4 |
| Поиск по классу | Плитки 9 классов и групп (грузовые, двухколёсные), период, канал, полоса, направление, линия, прицеп, кузов, марка. Плитки или список, выгрузка | 4.6 |
| Отчёт по полосам | Каналы × полосы × классы × период × шаг 15 мин / 1 ч / сутки. Сводный вид: матрица «полоса × класс» с итогами и долями и состав потока. Детальный вид: столбцы с накоплением и таблица интервалов с пиковым часом. Ячейка открывает поиск с тем же числом ТС. Выгрузка XLSX / CSV / PDF и по расписанию | 7.8, 7.5, 7.6 |
| События | События RoadAR без красных пунктов: сцена с траекториями участников, подтверждение, ложное срабатывание, передача ответственному, переход в архив | 6.1, 6.2 |
| Настройка сцены | Полосы с направлением, линии подсчёта, зоны въезда, зоны исключения, калибровка. Отправка в RoadAR повышает версию сцены | 1.2, 1.3 |

У поиска и отчёта есть переключатель демо-состояний «Данные / Загрузка / Пусто / Ошибка».
Канал CH-06 «Контейнерная площадка B» нарочно без сигнала с 11:07 — так видно,
как интерфейс показывает потерю канала.

## Какие решения прототип фиксирует

| Решение | Как выражено в UI |
|---|---|
| Числа сходятся между экранами | Счётчики детерминированы: в ячейке отчёта 306 автопоездов — в поиске «Найдено: 306» с теми же фильтрами |
| Контекст сквозной (п. 9.2) | Канал, полоса, класс и период переходят между экранами и видны в шапке; переход из отчёта сбрасывает только фильтры признаков |
| Отчёт по полосе строится с кадра | Клик по линии подсчёта на видео — мини-отчёт и кнопки «Отчёт по полосе» / «Найти ТС» (референс GoodVision) |
| Пиковый интервал выделен | Рамка «пик» на графике и подсвеченная строка в таблице (референс Miovision TMC) |
| Цвет ТС RoadAR не отдаёт | В атрибутах карточки — «не определяется», в фильтрах поиска цвета нет |
| ГРЗ вне пилота `[assumption]` | Номер показан только на CH-01 / CH-02 с LPR, поиска по ГРЗ нет (вопрос В-03) |
| Видео всегда тёмное | Сцена и кадр не меняются от темы — это видеоконтент, а не интерфейс |
| Цвета классов постоянны на всех экранах | Легковой — `accent`, лёгкий коммерческий — `teal`, грузовой средний — `amber`, тяжёлый — `orange`, автопоезд — `purple`, автобус — `green`, мотоцикл — `magenta`, велосипед — `fg-subtle`, спецтехника — `red` |

## Оформление: схема ONE PSIM

Кит взят из `ONE.PSIM.PrototypeKit` в режиме «create»: `kit/kit.css` — собранный
Tailwind с токенами `--one-*` для обеих тем, `kit/kit.js` — поведение тем, меню,
вкладок, диалогов и сегментов (`data-kit-*`). Свои стили лежат в `app.css` и
пользуются только токенами кита. При обновлении кита оба файла нужно скопировать заново и
повторить встраивание шрифта (см. `CHANGELOG.md`).

## Что осознанно вне области

- Нет бэкенда и реального видео: сцена нарисована в SVG, треки и счётчики генерирует `data.js`.
- Встраивание в клиент Axxon One (п. 9.1) не показано. Прототип показывает логику
  экранов, а не их место в клиенте (вопрос В-06).
- Нет ролей и журнала действий (раздел 9 спецификации).
- Карта, тепловые карты, сравнение периодов и прогноз (7.2–7.4, 7.7) не нарисованы —
  они не входят в пилот.
- Редактирование сцены мышью не реализовано, показан только состав элементов.
